# Crew — the Home screen plan (2026-09-10)

Owner-directed, from looking at the shipped TestFlight build on the phone. The complaint, verbatim:

> "This is the layout of the primary home screen I am looking at it and clearly don't know what to do next or what
> this screen is for or what the colors are for."

Three questions, and the screen answers none of them. This document is the builder's contract for fixing that. It
follows `docs/ux-plan-2026-09-09.md` in form: decisions first (Appendix A entry **A17**, authorised by the owner in
this session), then the work, then the checklist.

**Evidence:** a 41-agent review across eight lenses (layout, colour, week strip, vector row, information scent,
accessibility, crew strip/composition, outside research), each finding adversarially verified against the source —
62 findings, **52 confirmed, 10 refuted**. Every contrast ratio below was recomputed independently from
`ios/Crew/Generated/EmberColors.swift` and matches the agents' arithmetic exactly.

**The honest caveat, stated once:** every Home file is `WRITTEN — UNVERIFIED (needs Mac)`, there are no layout
snapshots, and CI selects the *newest* simulator (`ci.yml:95-102`), never the smallest. Every pt measurement here is
computed from tokens, not observed. **The owner's phone is currently the only layout harness.** §9 fixes that.

## 0a. A17 — the Decision Registry entry (owner-authorised 2026-09-10)

Drafted here, inserted into `docs/crew-mvp-spec.md` Appendix A by **H012**. Four amendments, each authorised
explicitly.

**A17.1 — Home carries visible copy.** A3 and A14 are the ratified *enumerations of Home's contents*, and both are
silent on captions, so the wordless header is an unexamined carry-over rather than a ratified silence. Home gains:
one ink summary sentence under the week strip built from facts it already computes; a "Your crew" caption on the crew
strip; and the streak stake folded into the existing rest-day line. **Every one is `secondaryText` ink and none is
ever tappable** — Ember laws ① and ③ are untouched. The bridge state is untouched (§1D): it carries one CTA and
nothing else, forever.

**A17.2 — the stack is reordered.** The flexible space moves from *below* the card to *above* it, so the day's single
ink-filled primary sits in the thumb zone on every state and the slack becomes a section break under the header
group. This is the first time 6.7's "primary actions stay bottom-anchored regardless of how much canvas exists above"
(`spec:973`) is literally true on Home — under A14 the filled primary sat above the Spacer on rest, all-done and
paused.

**A17.3 — the card's `extras` are removed on rest and all-done.** A3 requires "*a way* to post a meal, Log cardio,
and (rest / all-done) Bonus workout" — a way, not a dedicated button each. The vector row *is* that way, at a
position that no longer moves between states. This is the same argument the code already makes for workout days
(`HomeScreen.swift:80-82`). **It is written into the Registry so no future session re-adds them.** Seven controls
become five; the toolbar camera stays.

**A17.4 — three token/contract values move.**
- `ember` light **#FF6600 → #DF5908**. Measured 2.77:1 on the bone canvas, below 6.5's 3:1 graphical-object gate;
  the replacement measures **3.56:1**. Hue h24 → h23 — a one-degree shift, the same orange, 5% darker. Dark mode
  `#FF7A1F` (7.03:1) is unchanged. This repays `debt.md:16`, which already prescribed exactly this route, and it
  matters now because A16's macro tokens all pass and would make the flame the only failing colour in the app.
- The week strip gains a **fifth mark for the next training day only** (not all upcoming days). W040 specified four
  marks for five states; the shipped code, its own comment and the plan's prose all disagree with each other, and
  this settles it in the direction that answers the one question a rest day actually raises.
- Home's nav title becomes **per-state**, resolving the only tab/title disagreement of the five screens.

**Untouched by A17:** the gamification numbers, every rejected list, Ember laws ① ② ③ ④ ⑤ ⑥ (the *value* of `ember`
moves; no law changes and no second hue appears), the performance and accessibility budgets, `minimumAgeYears`, the
Concrete Doctrine, and every append-only vector. **A17 adds no vector and changes no engine rule.**

## 2. The eleven pure defects (no decision — they are simply wrong)

**D2.1 is a correctness bug that costs the user real state.**

1. **A paused plan can be un-paused into a full-credit workout.** `HomeScreen.swift:78` gates the vector row on
   `!isBridge` only, so it renders while paused. Its `onWorkout` calls `HomeModel.startWorkout()`, which returns a
   real session whenever `todayWorkout != nil` — and `todayWorkout` comes from a rotation projection that **never
   consults the pause** (`NextUpLine.swift:22-35`; `projectWeek` takes only `trainingWeekdays` and the cycle). So on
   a paused training day, tapping a grey box starts a session with `isPlannedDay: true` → **V25 +100 planned-day
   credit**. This is **F14 recurring verbatim**: the same pass fixed exactly this for Quick complete by gating on the
   *state* (`HomeModel.swift:71`, comment names F14) and the new row was written without the gate. Worse, on `.paused`
   the card renders zero controls, so the row is the only thing on screen inviting a tap. **Fix at the model**, so
   every present and future caller is safe.
2. `HomeScreen.swift:77` — `Spacer(minLength: sectionGap)` inside a `VStack(spacing: sectionGap)` is a **third gap**:
   24 + 24 + 24 = a hard 72 pt floor that persists even on a long scrolling day, contradicting the comment at `:57`.
   Web spends 24. → `minLength: 0`.
3. `Shared/WeeklyRing.swift:17` — the `days` parameter is still declared and **still never read**, the exact defect
   (F12) the week strip was built to fix. Delete it and its three call sites.
4. `Shared/WeeklyRing.swift:34` — `.accessibilityLabel` without `.accessibilityElement(children: .ignore)`, so the
   inner `Text("1/3")` may win and announce as "one slash three".
5. `WeekStrip.swift:33` — the comment claims "upcoming = the same tick, quieter" and "Four shapes". They are
   byte-identical: same token, same size. A distinction was described and never built.
6. `WeekStrip.swift:19` — `HStack(spacing: 0)` with no `alignment:` (defaults `.center`) while the web twin uses
   `align-items: flex-end`. The caption row rags in opposite directions, so a screenshot comparison cannot agree.
7. `CrewStrip` — no container accessibility label on iOS.
8. `web/src/app/(app)/home/page.tsx:40` — the member initial **and** the posted-dot are both `aria-hidden`, so a web
   screen-reader user hears a bare "1", and `aria-label` on a bare `<div>` is ARIA-prohibited.
9. **Twin divergence:** the Workout slot on a rest day opens `BonusWorkoutSheet` on iOS and navigates to `/plan` on
   web. Same slot, same state, two behaviours. Pick the sheet (`/plan` answers a question the user did not ask and
   leaves the screen) and make both match.
10. **Nothing on Home survives accessibility XXL.** `VectorRow` is a fixed 3-across `HStack` with no adaptive layout
    (`@ScaledMetric` scales height only): 375 − 32 − 24 = 319 / 3 = **106.3 pt per slot**, and "Workout" at AX4
    measures ~124 pt. `TodayCard.extras` is worse — 149.5 pt per button against ~182 pt for "Bonus workout", which
    wraps to "Bonus" / "worko…". `spec:974` names this exact case: *"no truncated CTA labels anywhere."* The remedy
    already ships twice (`SetRow.swift:42`, `UnitConfirmLine.swift:19`), so this is **C5's third occurrence** →
    extract into a plain function, do not duplicate a fourth time. `WeeklyRing.swift:33` also needs `@ScaledMetric`
    on its hardcoded 64 pt diameter.
11. **Four missing `debt.md` entries** (CLAUDE.md rule 9): the `missedGray` graphical-object sites at 2.39:1; the
    `hairline` / `secondaryButtonOutline` 1.26:1 on every outline control app-wide; the absence of spec 8.9's
    SE × XXL matrix; and the iOS/web Spacer floor divergence.

## 3. Layout (D2, D3)

**The diagnosis.** `HomeScreen.swift:77`'s Spacer is the **only vertically flexible child on the screen**, so all
leftover height lands at one seam. On rest / not-posted that is ~146 pt with the large nav title, ~175 pt for a solo
user, and **~245 pt (≈29%) on `.paused`**, where `TodayCard` renders two Texts and zero controls — a state A14 never
measured. The owner's observed ~22% sits inside that range.

**One correction worth stating plainly:** the thumb zone was never *dead*. `VectorRow` wraps every slot in a real
`Button` with a ≥44 pt `@ScaledMetric` frame, and the Meals slot is wired byte-identically to the rest-day primary.
The required action *was* reachable down there — it just wasn't labelled as the ask, and it wasn't the ink-filled one.

**The fix (D2 = card + button):** move the Spacer from `:77` to between the header group and the card. The card and
its filled primary land in the thumb zone; the slack becomes a section break under the week strip, where a gap reads
as rhythm rather than as a hole. On a workout day the card is long enough that the gap self-collapses. One line moved
— no new view, no new token, no engine change, no new vector.

**The fill (D3 = real facts):** the space above the card carries the **week summary block** — the same facts §4's
sentence names, plus the shield line when one is held. `HomeModel` computes `shields` (`:16,65`) and `lastAwards`
(`:24,54`) and **iOS renders neither** — the identical shape as the ring that ignored its `days:`. A user holding two
shields and a user holding none currently see an identical screen and an identical "One post keeps it lit."

The research is unambiguous on why this is the right fill rather than more whitespace: this was never too much
whitespace, it was too few content elements to justify it. *(Two claims from the review are explicitly NOT used as
rationale: the widely-cited "whitespace improves comprehension ~20% (Lin 2004)" is a **misattribution** — Lin studied
hypertext retention in older adults and says nothing about margins; and **choice overload does not survive
meta-analysis** (Scheibehenne, Greifeneder & Todd 2010, 63 conditions, N=5,036, effect ≈ zero), so the argument for
§6's de-duplication is **ranking legibility**, not option count.)*

## 4. Words (D5, D6, D8, D19)

**The diagnosis — this is complaints (2) and (3), literally.** Four elements each build a complete English sentence
and render it **only to VoiceOver**:

| Element | To the eye | To VoiceOver |
|---|---|---|
| `StreakFlame.swift:17,23` | flame glyph + `1` | "Streak 1" |
| `WeeklyRing.swift:29,34` | `1/3` | "1 of 3 workouts done this week" |
| `WeekStrip.swift:22,50-56` | `M T W T F S S` + 7 marks | "This week: 1 workout done, 1 missed" |
| `CrewStrip.swift:21,28` | avatar + dot + `1` | "MC, streak 1, not yet today" |

Between `.navigationTitle("Today")` and the card, a sighted user gets a glyph, two bare numerals and seven dots. The
web twin is identical, so this is a design-wide pattern, not an iOS slip. **`VectorRow` is the on-screen proof that a
title-plus-value caption is legal here** — it already ships visible titles; the header block simply never got one.

**The sentence (D5).** One ink line under the strip, built from facts already computed:

> `This week: Wed done · Mon missed · next Sun`

It names the colours *in situ*, so there is no legend to look up — and a legend would cut against A16's own ratified
"direct numeric labels, never a colour-only legend". It explains why the ring says 1/3. It answers "when do I train
next" where the eye already is.

This is a formatting rule shared by two platforms → a **twin pair**, `WeekSummary.swift` ⇄ `week-summary.ts`, with
unit tests on both sides. **D19 makes the VoiceOver sentence the same function**, extended to name days in full
("Wednesday done, Monday missed, today Thursday, next workout Sunday") — one sentence, staying inside E20's "one
sentence, not seven stops", and it can never drift from what is on screen because it is the same code.

**Three hard constraints on the sentence:** it is `secondaryText` ink and never `#B84D00` (law ③); it is never
tappable (law ①); and it is **bridge-gated** like the ring and strip. `StreakFlame` at `HomeScreen.swift:66` is
currently *not* gated, and on the bridge `streak` is 0 — so an ungated caption would put a noun beside a
zero-as-verdict (A8) on the one screen §1D says carries nothing extra.

**The stake (D8).** "One post keeps it lit" never says what "it" is. Fold it in: *"Post anything today and your
1-day streak holds."* No new element, no countdown, no notification — `spec:452` ("Weights & calories never pressure
you") and the no-nudges doctrine sit right beside this, and a risk countdown on Home is the shape of the thing this
app was built not to do.

**The title (D6).** Per-state: "Rest day" / "Push day" / "Done for today" / "Plan paused". The title answers "what is
today" before anything else is read, and it ends the only tab/title disagreement of the five screens.

## 5. Colour and contrast (D9, D10, D11, D12)

**The root cause is a documented conflation.** `WeekStrip.swift:9`, `ux-plan:600` and the web twin all certify 6.5
because the marks "carry a shape as well as a colour, so the strip reads in grayscale." That answers **WCAG 1.4.1**
(colour is not the only channel). It says nothing about **1.4.11** (non-text contrast), which is the gate `spec:960`
actually states. **No contrast test exists anywhere in the repo.**

Measured against canvas `#FAF8F5` (the strip is not inside a card) and card `#FFFFFF` — recomputed independently:

| Mark | Source | Now | After |
|---|---|---|---|
| rest / upcoming dot | `WeekStrip.swift:44` | `hairline` **1.19:1** | `secondaryText` **5.18:1** |
| missed ring | `WeekStrip.swift:42` | `missedGray` **2.39:1** | `secondaryText` **5.18:1** |
| done mark | `WeekStrip.swift:38` | `ember` **2.77:1** | `ember` **3.56:1** |
| today ring | `WeekStrip.swift:40` | `inkText` 15.79:1 ✓ | unchanged |
| unlogged vector dot | `VectorRow.swift:46-49` | `hairline` **1.26:1** | `secondaryText` **5.49:1** |
| crew not-posted dot | `CrewStrip.swift:17` | `missedGray` **2.53:1** | hollow `secondaryText` ring **5.49:1** |

**D9 — recolour, don't restyle.** Point the faint marks at the existing `secondaryText` token. Still warm gray, so A8
holds; never orange, so the laws are untouched; no token file edited, no `Generated/` edit, no amendment. It works in
dark mode too, because the *token reference* changes, not a value: dark `secondaryText` `#A69E94` is 6.93:1 on dark
canvas and 6.33:1 on dark cards, where `missedGray` dark is 2.58:1 and `hairline` dark is 1.26:1. **Do not thicken
strokes as a "fix" — line weight does not change a contrast ratio.**

**D10 — repay the ember debt.** `#FF6600 → #DF5908` (2.77 → **3.56:1**), light mode only. Same hue (h24 → h23), 5%
darker. `emberText` `#B84D00` (4.83:1, the text gate) and `emberTint` `#FFEFE3` (the ring track, decorative — the
fraction inside the ring is ink) are unchanged. This is a Part III table value and every snapshot moves; it is
authorised as A17.4.

**D11 — the slots stop looking disabled.** `VectorRow.swift:55-56` paints `card` fill + a 1 pt `hairline` border —
**character-for-character the chrome of the read-only `Card`** (`Shared/Card.swift:13-14`). The border measures
1.26:1. Drop the card fill so the card/canvas step does the separating, and give the slot an ink verb. *(The same
`#E9E4DD` outline is on every `SecondaryButton` in the app at 1.26:1 — what rescues those is an ink `.headline`
**verb**, which is exactly what the slot omitted. The app-wide `controlOutline` sweep is **out of scope here** and
goes in `debt.md` for a separate ratified pass.)*

**D12 — the crew dot gets a shape.** Posted-vs-not-posted is currently colour alone. `spec:290` literally calls it
"the **empty** today-dot", so a hollow ring for not-posted is the *conforming* rendering — it fixes a spec deviation
and a WCAG 1.4.1 gap in one change.

**H018 makes this permanent:** a contrast test over `design-tokens.json` asserting every foreground/background pair
Home uses clears its gate (3:1 graphical, 4.5:1 text) in both modes. Without it the next token change re-breaks this
silently, exactly as it broke the first time.

## 6. The vector row (D4, D7, D11)

**Seven controls, three destinations.** On rest(not posted), rest(posted) and all-done:

| Destination | Reached by |
|---|---|
| `posting` | toolbar camera · card primary · Meals slot — **three ways** |
| `loggingCardio` | card `extras` · Cardio slot |
| `choosingBonus` | card `extras` · Workout slot |

The row's *unique* contribution per state: workout day **one** (Cardio — the card has no extras there) · rest
**zero** · all-done **zero** · paused **two**.

The harm is sharper than clutter. On rest(not posted), "Post a meal" is the only ink-filled control and its rank is
diluted by two outline restatements of itself. On **rest(posted)** and **all-done** the card's meal button is a
`SecondaryButton` — so those seven-control screens carry **zero ink-filled primaries**. "One primary action per view"
fails there in the letter, not just the spirit.

**D4 — drop the card's `extras`.** Seven → five; each destination shown at most twice. It also collapses the card by
~56 pt, which slightly worsens §3's void — so it ships **paired with the §3 fix**, not before it.

**Forward risk, recorded now:** A15's "Change today's workout" sheet routes "do a different day" to the same bonus
list. That becomes a **fourth** control for `choosingBonus` if this is not collapsed first. This is why D20 holds
Stage 7 until Home is settled.

**D7 + D11 — the slot becomes an invitation.** `Workout / Log`, `Cardio / Log`, `Meals / Log`, with the empty value
as an ink verb rather than an em dash. *(The em dash is spec-blessed on **input** surfaces — `spec:203`, "'—' is a
complete set forever" — but its use on a **status** surface was never ratified: Appendix A ratifies A9–A15 "as
implemented through **Stage 5**", and the row is Stage 6. The plan's own §3 mock draws "Meals 2/3", never a dash.)*
A near-invisible hollow ring beside an em dash is the universal idiom for *disabled* — and today VoiceOver hears
"Cardio, nothing logged today, **button**" while the eye sees a dead cell, so the accessibility affordance is
strictly better than the visual one.

**Not doing:** making the slots read-only. On `.paused` the card renders zero controls, so the row is the screen's
only interactive surface; making it inert leaves a screen with nothing to touch.

## 8. The crew strip (D15, D16)

**D15 — a crew of one is suppressed.** `HomeModel.swift:165-168` returns nil only when *no snapshot exists*; a crew
of one has a snapshot whose members are `[you]`. **The Crew tab already knows better** — `CrewModel.swift:37`
`isCrewOfOne` on `SpecConstants.crewMinMembers` (= 2). Home is the last surface treating a crew of one as a crew.
Reuse that exact one-line predicate (C5: duplicate, don't extract). *True solo is already correct* — no snapshot →
nil — so S07 and Flow 10 were always satisfied; the defect is the distinct crew-of-one state A5 governs.

**D16 — caption and separation.** An ink "Your crew" caption, a container accessibility label, and `sectionGap`
instead of `rowGap`. Today `HomeScreen.swift:79-88` binds the vector row and the crew strip in one
`VStack(spacing: rowGap)` — **8 pt, the gap `design-tokens.json` documents as "within one group"** — while every real
boundary on the screen is 24. The layout currently asserts the crew avatar is a fourth vector slot.

**Not doing:** an invite CTA on Home. That would add a second primary action.

## 9. Layout coverage (D18)

Spec 8.9 (`spec:1124`) requires S07 Home at SE 375×667 and Pro Max 440×956 × {default, XXL}, diffed in CI. **It has
never been built.** `Screenshots.swift` is ad-hoc attachments whose own header calls it "the first step toward" the
matrix, and `debt.md:11` promises repayment "by the 8.9 snapshot matrix" — a matrix that does not exist, and whose
absence is itself unrecorded. 8.9 is a Phase 5 exit criterion, so the gate reads green on paper while being unmet.

**D18 — assert properties, not pixels.** Pixel baselines must be *recorded* on a Mac, and there isn't one. Instead
assert the invariants that actually matter, in the existing CI job: nothing exceeds the 375 pt window; no CTA label
truncates at XXL; the day's filled primary sits below the vertical midpoint; the void never exceeds a stated
fraction. Plus one line in `ci.yml` so the simulator selection includes an SE-class device rather than always the
newest. Both are cheap, both run today, and neither needs hardware this project does not have.
